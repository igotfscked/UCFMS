# UCFMS
Unclaimed funds data management system

I started this project in 2023, with the intent of learning more about mainframe- native application development, and it has grown into a project that has led me deep into not just COBOL application programming, but a deep dive into what it was like to build programs for the mainframe environment,

The target build environment is OS/390 V2R10, which is an operating system for the IBM System/390 (and later) series mainframe systems - currently known as the z/Series, with the latest system model being the z17, and the latest OS release being z/OS 3.2z

While I have a real, physical mainframe system available (a System/390 Multiprise G5, type 9672-B22) I decided to use an emulated system under Hercules (the Hyperion release) using the IBM OS/390 V2R10 ADCD distribution, which is commonly available for download, so others can easily reproduce the required baseline environment without having to have a real mainframe.

I have included the scripts to create the DASD images and the JCL files to load the data files into the datasets on each volume, as well as the field definitions for the Texas unclaimed funds data, but due to the licensing and distribution restrictions on the data per the Texas Comptroller’s office, I can not release the data files - you will have to contact the Comptroller’s office to request a copy of the actual data; be aware that this data (as of my most recent download in 07/2026) is over 16 GB of uncompressed text, some 17 million records, and requires a 3390-27 CKD volume (about 40 GB of disk space to hold the emulated disk volume file) 

For anyone wanting to port this to the MVS 3.8j Hercules environment, be aware that the latest 3390 DASD volume type that 3.8j supports is a 3390-9, approximately 1.1 GB in size - it won’t be able to use any larger volume or later model, just FYI.

In addition, I have also included the data field definitions for the Social Security Death Master File (DMF) which is publicly available current to 2011, with newer updates requiring subscription payment to the appropriate agency; I have also included the JCL required to load the data files from source.

## What's in this repository

Search and claims tooling for the Texas Comptroller's unclaimed property
records: find records by owner last name or business name, holder name, owner
ZIP, or combinations such as property type code plus ZIP, then track claims
and fill the Comptroller's claim forms.

The project has two tracks:

- **A working search prototype** in Python and SQLite with a local web page
  (standard library only, tested).
- **A z/OS design** for the production system: VSAM files loaded from the
  Comptroller's tape, JCL, COBOL utilities, and an ISPF + CICS application
  design (Query, Claims, Reports, Admin). The JCL and COBOL have not yet been
  run on a mainframe, and site values are placeholders.

## Search prototype (Python)

Loads the Texas Comptroller's fixed-width unclaimed property file
(layout in [LAYOUT.md](LAYOUT.md), 469 chars per record; property type
codes in [PROPERTY_TYPES.md](PROPERTY_TYPES.md)) into SQLite and
searches it from the command line or a local web page. Python 3.9+ standard
library only; nothing to install.

### Use

```sh
python3 -m ucfms --db ucf.db load /path/to/ucf_file.txt   # add --replace to start fresh
python3 -m ucfms --db ucf.db serve                         # http://127.0.0.1:8000/
python3 -m ucfms --db ucf.db search --owner-last smith --zip 78701
python3 -m ucfms --db ucf.db search --property-type AC01 --zip 787
python3 -m ucfms --db ucf.db types                         # codes, descriptions, which are loaded
```

Keep the `.db` file on a local disk (SQLite is slow and unsafe on network shares).

### Search filters (all combine with AND)

| Filter | Matching |
|---|---|
| Owner last name / business | starts with, case-insensitive (`smith` finds SMITH, SMITHSON) |
| Owner first name | starts with |
| Owner name words | whole words, any order, prefix per word (`acme gas`) |
| Holder name | starts with |
| Holder name words | whole words, any order (`bank america`, `heb` finds H-E-B) |
| Owner ZIP | 3–4 digits = prefix, 5 = exact ZIP, 9 = exact ZIP+4 |
| Property type | exact code; the web dropdown lists all 116 codes with descriptions |
| Owner city, state, holder report year | city is starts-with; others exact |
| Minimum amount | DollarAmount >= value (dollars) |
| Property ID | starts with, over holder ID + year + type + sequence |

Web page: paging, sort (name/amount/holder/ZIP), click a row for every field,
Export CSV (up to 50,000 rows). JSON API: `/api/search?owner_last=...&zip=...`,
`/api/record?id=`, `/api/meta`, `/api/export.csv`.

### Parsing rules

- Lines may end in CRLF or LF. A file with no line breaks is read as a stream of 469-byte records. Short lines (trailing blanks trimmed) are padded. The load reports any line that is not exactly 469 bytes.
- Encoding is read as latin-1 (change it with `--encoding`).
- DollarAmount has implied cents: `0000006270` = $62.70 (default `--implied-decimals 2`). The raw text is kept.
- Property ID search matches from the start of holder ID + year + type + sequence.

### Test

```sh
python3 -m unittest tests/test_ucfms.py -v
python3 -m ucfms sample sample/ucf_sample.txt -n 1000   # synthetic, fake data
```

Measured on 500,000 synthetic records: load 15 s, DB 270 MB, searches
40–250 ms including Python start-up.

### Getting the real data

The full file is not a free public download. Per the data.gov listing
(<https://catalog.data.gov/dataset/texas-unclaimed-property-listing>), it is
requested from the Comptroller at up.dbrequests@cpa.texas.gov (name, company,
mailing address, phone, and Texas PI license number if applicable). Single
lookups are at ClaimItTexas.org.
